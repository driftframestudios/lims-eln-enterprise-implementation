# Proportionate recovery routing

## Contract

- **What:** A repository-local method for selecting one fitting recovery move
  after an observable Enterprise proof or coordination strain.
- **When:** A configured environment check, exact source relation, release
  carrier, permission boundary, or collaboration handoff cannot yet support
  the next reliable decision.
- **Boundaries:** Recovery preserves accepted source, sealed release artifacts,
  exact digests, credential boundaries, publication limits, and accountable
  decision authority. This skill selects and verifies a recovery route. Its
  result stays at the existing assurance stage.
  `configured-environment-evidence-binding` supplies environment facts and
  admits a configured observation after the route returns it. Accountable
  acceptance remains a separate decision.
- **Result:** The receiver can identify the observed strain, protected
  contract, owning surface, one primary move, stopping event, compact receipt,
  restored dimensions, remaining strain, and exact re-entry condition.

## Rules

### Rule: Observable state comes before a failure explanation

Record the failing check, status class, exact commit or dependency coordinate,
unavailable source, or conflicting carrier and state its consequence for the
current decision. Treat a failure geometry as optional attention shorthand for
selecting the move, never as a label for a person, collaborator, or system.

### Rule: The route serves the highest-consequence invariant

Keep accepted release subjects, signed tags, public-inspection identities,
database migration order, fixed digests, protected values, and named authority
intact. Improve convenience or structure after the route has preserved the
invariant that gives the evidence meaning.

### Rule: One primary move has one owning surface

Choose the narrowest surface that can change the affected state. Source
alignment belongs in source; runner configuration belongs in the workflow;
repository access belongs with the credential or repository owner; and
acceptance remains with its accountable receiver. Supporting checks can inform
the move while one surface owns its result.

### Rule: Repeated execution requires a changed signal

Name the stopping event before another execution. A new attempt follows a
changed source revision, dependency or image coordinate, configuration,
permission, environment, or diagnostic capability that could alter the
result. Preserve an unchanged result as the receipt for the present route.

### Rule: Recovery selection and evidence admission remain separate

This skill identifies how work can resume and verifies that the selected
dimension became workable. The configured-environment-evidence-binding skill
then checks exact commit, tool, runtime, database, scenario, artifact, run, and
review coordinates and admits the resulting observation at its supported
assurance stage. Either skill can complete while production authorization,
organizational acceptance, or a successor exercise remains open.

### Rule: Activation uses current authority

Perform the selected move only through authority already present in the task.
When the move needs a different permission, environment, or accountable
decision, hand it to the receiver who owns that authority and retain the exact
event that permits re-entry.

### Rule: Receipts state reach before boundary

State what the recovery observation establishes, then name what it leaves for
a different receiver or environment. Keep credentials, raw runner output,
private locators, headers, and protected response data with their existing
authorized owner. A public-safe return carries the smallest decision-changing
summary.

### Rule: Dimensional verification replaces a single pass/fail label

Name the dimensions restored and the dimensions still awaiting evidence.
Source alignment can be restored while hosted execution is pending; hosted
execution can be observed while production acceptance remains with environment
owners. Each signal carries only the reach it can establish.

### Rule: History and re-entry stay reachable

Preserve the earlier result, changed prerequisite, exact successful source,
and current handoff through their existing pull request, workflow, receipt,
release carrier, or branch record. Add another recovery artifact only when it
changes a future decision.

## Operating sequence

1. **Recover the contract:** Resolve the current task, accepted source,
   immutable release boundary, evidence stage, and exact state from which work
   should resume.
2. **Record the strain:** Name the observable cue, decision consequence, prior
   attempts, and evidence already available.
3. **Read the geometry:** Determine whether the gap is useful, neutral,
   coordination-blocking, harmful, or still unknown. Preserve a useful gap and
   gather only the smallest discriminating observation for an unknown one.
4. **Protect the invariant:** Carry forward exact identities, privacy,
   permission, publication, release, and decision-authority boundaries.
5. **Select scope and owner:** Choose the smallest surface that can change the
   affected state and keep adjacent workstreams at rest.
6. **Choose one move:** State the primary action, its permitted effect, the
   changed signal required before retry, and the stopping event.
7. **Activate with authority:** Perform the move through present authority or
   hand it to the receiver who can change the affected state.
8. **Verify the replacement state:** Use the smallest observation that answers
   the recovery question and distinguish restored from remaining dimensions.
9. **Hand evidence to its owner:** Route any configured result to
   `configured-environment-evidence-binding`; route acceptance or production
   authority to its named human or environment owner.
10. **Return to the work:** Leave the current source, compact receipt, next
   receiver, and exact event that permits re-entry.

## Source and transfer note

This Enterprise derivative preserves the Program repository's Recovery Routing
and Failure Geometries distinctions: observable strain, gap utility, smallest
adequate scope, one owning surface, authorized activation, decision-bearing
receipt, dimensional verification, and exact re-entry. Its representative
scenario is repository-local evidence; it demonstrates fit for this route
without making the example a universal sequence.

## Completion

Recovery routing completes when the selected dimension has a verified workable
replacement state or the remaining move rests with a receiver that can change
it, and when another collaborator can resume from the named source, receipt,
and re-entry event. Evidence admission remains complete only when
`configured-environment-evidence-binding` accepts the returned configured
observation. A materially different geometry, a near miss, or a receiver that
cannot act reopens this derivative for revision.
